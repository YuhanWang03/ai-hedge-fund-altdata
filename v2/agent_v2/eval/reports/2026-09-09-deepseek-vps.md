四处修复，每处都对应第一轮里的一个具体失败：

1. **证据 id 冲突不再致命。** 同一只票的两份真实录制（不同时间的引擎运行）在同一个
   内容哈希 id 下带着刷新过的数字，账本判为冲突让整次 run 崩溃，5 个 compound 用例
   零次模型调用就失败。现在后来者重新编号为 `<id>~<producer>`，两条事实都可引用并披露。
2. **失败的数据卡也可引用。** EDGAR 超时后结果没有任何证据，模型只能编占位引用，
   校验器拒绝，回退摘要丢了"超时"。fixture 现在和生产适配器一样为限制生成证据条目。
   这就是 3 次"重写丢事实"的全部来源。
3. **LLM 规划器接到 FAST_LOOKUP。** 之前只有 RESEARCH 路由会问模型，"我这个月比上个月
   表现好还是差"这类措辞规则没覆盖、模型也没看到。现在规则给出空计划或只有范围读取时
   由模型补充，任务合并到规则计划上。留出集 x02 由此从三次全败变为三次全过。
4. **合成提示先答所问的量。** 简洁风格让模型省掉了问题直接问的数字（总市值、周亏损额、
   被比较的名字）。开发集 V1 卡片层 v2_llm 从 91% 回到 96%，fallback 从 19% 降到 8%。

**校验器轴。** 两轮四组里"校验器疑似误报"都是 0，即没有一份答案键全部通过的回答
被校验器拒绝。第一轮的 3 次"重写丢事实"是修复 2 的对象，第二轮为 0。

## 剩下的失败在哪

留出集（未调，三轮只看不改）：

| 用例 | 问题 | V2 做了什么 | 答案键要什么 | 判断 |
|---|---|---|---|---|

| x05 | NVDA 的供应链上下游里，有哪几家我也持有？ | research.stock（供应链） | 加 account.portfolio | "我也持有"带 ticker 时没被识别为账户范围 |

| x12 / x13 | 我的持仓最近整体在跌还是涨？ | 逐只异动解释 ×6 | account.performance（当日盈亏） | "整体"应走账户盈亏，不是逐只展开；这也是留出集里最贵的一例 |

这四类是措辞覆盖问题，不是架构问题。按留出集纪律它们不该再靠加正则修；正确做法是把
这 15 条并入开发集，从 Telegram 实测里另抽一批新的留出集。

开发集：m08 和 r02 是 fan-out 上限 6 而持仓有 8 只，SMCI 被截掉；k04"CRWD 占仓多少"
和 d02"要不要减仓"没触发账户能力。这三处已在报告随附的提交里修复（开发集允许调）。
k01、r02、r08 各有一次三取一的模型漏写，属噪声。
