四处修复，每处都对应第一轮里的一个具体失败：

1. **证据 id 冲突不再致命。** 同一只票的两份真实录制（不同时间的引擎运行）在同一个
   内容哈希 id 下带着刷新过的数字，账本判为冲突让整次 run 崩溃，5 个 compound 用例
   零次模型调用就失败。现在后来者重新编号为 `<id>~<producer>`，两条事实都可引用并披露。
2. **失败的数据卡也可引用。** EDGAR 超时后结果没有任何证据，模型只能编占位引用，
   校验器拒绝，回退摘要丢了"超时"。fixture 现在和生产适配器一样为限制生成证据条目。
   这就是 3 次"重写丢事实"的全部来源。
3. **LLM 规划器接到 FAST_LOOKUP。** 之前只有 RESEARCH 路由会问模型，"我这个月比上个月
   表现好还是差"这类措辞规则没覆盖、模型也没看到。现在规则给出空计划或只有范围读取时
   由模型补充，任务合并到规则计划上。留出集 x02 由此从三次全败变为三次全过。
4. **合成提示先答所问的量。** 简洁风格让模型省掉了问题直接问的数字（总市值、周亏损额、
   被比较的名字）。开发集 V1 卡片层 v2_llm 从 91% 回到 96%，fallback 从 19% 降到 8%。

**校验器轴。** 两轮四组里"校验器疑似误报"都是 0，即没有一份答案键全部通过的回答
被校验器拒绝。第一轮的 3 次"重写丢事实"是修复 2 的对象，第二轮为 0。

## 多智能体化第一步：申报阅读者

这一节记录三轮评测之后在线上追的一条对话链，以及为它加的第一个子智能体。它不在
前面的表格里：那些用例都是单轮，而这条链的价值在第二轮。

**对话。** "我的仓库里哪只跌的最多？" → "为什么跌这么狠？"。第一问由规则从持仓卡直接
答（ARM，买入以来 -32%）；第二问要接上"买入以来的浮亏"这个框架，而不是解释当天的涨跌。

**架构不变的部分。** 协调者仍是一个：路由、规划、执行、合成、校验各一处。子智能体
被放在能力接口之下，对协调者而言只是一个新能力 `filings.read_events`：参数进，带来源
的证据信封出。它不能自行启动（由回撤计划按最差交易日 fan-out 触发），不能对用户说话，
不能引用没读到的文字（引文在已读章节里定位不到就丢弃）。

**申报阅读者的约束。** 列出目标日前 14 天到后 3 天的申报（8-K，外国发行人转 6-K），取
最近两份，正文按 Item、标题或固定长度切成不超过 20 节，6-K 把 EX-99 附件并入；模型每轮
只能"读最多 3 节"或"结束"，至多 6 轮、90 秒，轮次用完再给一次只允许结束的调用；报出的
每个事件必须有日期、概括和引文，引文按匹配片段在原文里定位并替换为原文。

**线上迭代，每一步都是一次真实提问暴露的。**

| 版本 | 现象 | 修法 |
|---|---|---|
| 阅读者上线 | 三个最差交易日只跑了前两天，有申报的第三天被 fan-out 上限截掉 | 上限改为与最差交易日数一致（3） |
| 同上 | 6-K 主文件只是封面 | 并入 EX-99 附件 |
| 附件并入后 | 目录切到 150 多节，4 轮全用来选章节，没来得及输出 | 目录合并到 20 节内；6 轮 90 秒；一轮读 3 节；轮次用完强制收尾 |
| 收尾后 | 找到 7-29 业绩事件，引文差一个连字符被判不符而丢弃 | 引文按匹配片段定位，替换为原文 |
| 网页步启用后 | 新闻只搜了两天；摘要正文没日期被过滤成"未查到" | 网页也覆盖三天；按标题和发布日期渲染 |

**最终一次线上运行**（DeepSeek，用户授权网页，服务端启用 Web）：7 个工具、45 条证据、
22.7 秒、模型回答（修复一轮）、校验通过、1 条警告。回答把 6-23 归为韩国芯片指数暴跌引发
的系统性抛售、7-24 归为财报前仓位调整、7-29 归为业绩创纪录但市场按 AI 芯片情绪定价，
并明确写出"核对了 7 月 15 日至 8 月 1 日的 SEC 申报，业绩与股东信均为正面，未发现与下跌
相关的负面事件"。与最初"证据列表为空，无法判断"的回答相比，这条路径从零走到了带原文
引用的多源归因，每一处"没找到"都写了出来。

**代价。** 用到子智能体的问题比普通研究问题多 3 到 6 次模型调用、多 10 到 20 秒；三条
阅读路并行，墙钟增量约等于最慢的一条。不涉及回撤框架的问题完全不受影响。

**评测。** 这条链固化为种子集里的 5 条两轮场景（`scenario_cases.py`）：回撤归因、回撤
归因加网页、代词追问、"为什么涨"不走回撤、无上文不改写。它们用同一套离线 fixture，零
模型，秒级跑完，作为后续加多空辩手时的回归门槛。协作类指标在这里的定义是"子智能体参与
的用例通过率提升了多少、多花了多少"，而不是智能体之间对话的质量。

## 多智能体化第二步：今日归因、新闻核查者、子智能体可观测

**今日涨跌也走归因者。** "NVDA 今天为什么跌" 之前是单跳的今日涨跌解释（V1 的异动
归因），与回撤链里的归因者做同一件事却不同实现。现在 `market.explain_move` 由归因者
在最新一根日线上执行：当日或前 3 天内有申报先读、有网页授权则搜新闻、查盯盘记忆；
盘中时价格与成交量按"截至查询时"口径措辞并带校验规则，收盘前不写记忆。信封仍叫
`market.explain_move`，路由、回答指引和评测不变；没有模型时保留 V1 实现。

**网页步改成新闻核查者。** `web.research` 之前是一次 Tavily 搜索、摘要即证据。现在有
模型时它是一个有界子智能体：最多 3 次搜索、3 篇正文（Tavily 返回的原文）、6 轮 75 秒；
报出的每条事件必须有 ISO 日期、指向本轮拿到的结果、引文能在读过的正文或摘要里定位，
否则丢弃并计数。没有模型时仍是原来的摘要适配器。

**子智能体可观测。** 脚手架为每一轮记录动作、参数摘要和耗时；申报阅读者、异动归因者
（含它调用的阅读者）、新闻核查者都把 `agent`（轮次、调用数、停止原因、允许秒数）和
`trace` 写进信封元数据；结果的 `sub_agents` 字段汇总它们。Telegram 在来源之后列出
"子智能体"段（每个一行，嵌套的阅读者缩进），网页端在"执行工具"里可逐轮展开。

## 多智能体化第三步：评测、记忆治理、规划器派活、反方

**子智能体评测（5）。** 每次线上运行给每个子智能体写一行账本（`data/agent_v2_subagents.jsonl`）：
轮次、调用数、耗时、停止原因、产出（校验后保留的原因/事件数与被丢弃数）；模型调用在用量
账本里按 `agent_v2.<name>` 归属（规划器、合成器、反方也各自记账）。
`python -m v2.agent_v2.eval.subagent_report --since 7` 汇总每个子智能体的运行数、平均轮次、
平均和 P90 秒数、停止原因分布、每次产出、丢弃率、空跑数，以及按来源的 token 用量。
成本不用钱看：DeepSeek 高峰和空闲时段价格不同，钱数没法跨时段比。报告把每次调用折成
**标准 token 当量 = 未缓存输入 + 缓存输入 / 30 + 3 × 输出**（三类 token 的价格比例在两个时段
一样），给出每个来源的当量、当量/调用、当量/次运行和缓存命中率；账本有价格版本时钱数只作
末尾一列。

**记忆治理（7）。** 归因写回的 `retro_attribution` 记录带上版本、最高置信度、首要原因和写入
日期；后一次只有候选解释的运行不会覆盖已有的高置信度记录；覆盖时首要原因变了就记下
上一次的结论并写进回答的说明，漂移可见。召回时记录显示置信度和写入日期。

**规划器派活（2）。** 模型规划器看得到哪些能力是子智能体，一份计划最多 2 个、fan-out 最多
3 次，超出的被丢弃并写进假设；含子智能体的计划至少 60 秒预算。"两只股票最近为什么走势
分化"由模型对每只分别安排区间回报和今日归因。

**反方（4）。** 归因者报出高置信度驱动后先过一道算术：行业基准同向且占了涨跌的大部分，
驱动降为中置信度并说明；再用一次模型调用找具体反对理由（幅度、时间、是否只是观点），
只有具体成立的反对才降级，无论采纳与否都写进说明和子智能体摘要。

## 多智能体化第四步：反方辩手、离线评测里的子智能体

**反方辩手。** 研究类问题的回答在校验通过之后，再由反方过一遍：给它问题、回答和本次运行
的证据列表，它找出 1 到 3 个最站不住的判断，每条反对必须指向本次证据里的一个 id（相反的
数字、被忽略的限制、口径不符），指不到的丢弃。反方不改写回答，它的反对作为一个子智能体
记录（`debate.challenge`）附在回答旁边：Telegram 的子智能体段、网页端"执行工具"里可展开。
预算上是一次模型调用，只在剩余时间不少于 20 秒时进行；`AgentV2Config.debate=False` 关闭。

**离线评测里的子智能体。** 场景假数据的归因结果带上 `agent` 和 `trace`，场景用例可以要求
"某个子智能体至少运行 N 次且都正常结束"（`expected_agents`），评测输出多了 `agents=` 和
`sub_agents=` 两栏。回撤、上涨、直接进入三类场景都要求异动归因者运行过。

## 去正则第一步：意图分类影子模式

路由和规则规划器靠 70 条正则把用户的话翻译成要跑的任务，每种新问法补一条。
第一步不改行为：每个线上问题在后台多一次便宜的模型调用（`agent_v2.intent`），把问题归成
固定字段（kind、scope、direction、wants、tickers、portfolio_scope），和路由、计划反推出的
同一组字段并排写进 `data/agent_v2_intents.jsonl`。
`python -m v2.agent_v2.eval.intent_report --since 7` 给出每个字段的一致率和逐条不一致
清单。一致率决定第二步（意图驱动路由，正则退为兜底）什么时候切；第三步把规划模板改成按
意图字段触发，正则逐批退役。

## 子智能体换成通用工具循环

`agents/base.py` 新增 `Tool`（名字、说明、JSON schema、handler）和 `ToolLoop`：子智能体把工具声明
一次，循环用模型的原生 function calling 驱动，每轮执行一个工具调用，`finish` 也是一个工具，参数就
是子智能体的报告 schema。模型若用文字输出 JSON 动作仍能识别，所以旧的脚本化测试不用改。
每个工具调用都会得到一条 tool 消息（多余的调用回"未执行"），transcript 对提供方始终合法；
handler 抛 ValueError 时原话回给模型，其他异常回"执行失败"。未提供的工具（未授权网页、没有记忆）
不出现在工具列表里，模型硬要调用时得到原因。申报阅读者、异动归因者、新闻核查者三个已迁移：
各自的 handle 分支变成了三五个独立的 handler 函数，提示词只描述工具的用途，不再教 JSON 格式。

## 输出侧的措辞规则改由模型判定

校验器原来用正则禁止回答里的某些说法（"申报内容未读取"、"主要原因"、"缩量"、"0 个驱动"），
模型换一种措辞就漏过去，"正文未读取"就是一例。现在这些规则是一句自然语言的断言
（`{"forbid_claim": "申报的正文或内容没有被读取", "warning": ...}`），什么时候适用仍由规则从数据里
判定（阅读者确实读了申报、行情确实是盘中、这条确实是候选解释）；适用时校验器把回答里引用
该证据的句子和断言交给 `ClaimJudge`，一次模型调用判定整份回答的全部断言并引用原句
（`agent_v2.judge`）。合成器的初稿和修正稿都过这一道，没有模型时这类规则不生效。
盘中价格、盘中成交量、候选归因、内部计数、申报未读取五条规则全部换掉，输出侧不再有措辞正则。

## 去正则第二、三步：意图驱动路由和规划

路由和规划器不再读字面。`intent.py` 的 `Intent` 是一组固定字段：kind、scope、direction、wants、
tickers、portfolio_scope、watchlist_scope，外加命令参数（operation、ticker、direction、price、alert_id）、
宏观数据名、基金经理、ARK 代码、回撤窗口、研究维度、实验类型和策略、盈亏口径、排名方向。线上由
`IntentClassifier` 一次 function calling 调用产出（`agent_v2.intent`，约 1.5 秒）；没有模型时用
`eval/recorded_intents.json` 里按原文记录的标签（500 多条，覆盖测试和离线评测用到的全部问题，
是旧正则管线删除前投影出来的）；没有标签的文本走默认意图（有代码就研究概览，没有就查询），并在
计划假设里注明。`routing.route()` 从意图定路由，`planning.IntentPlanner` 从意图套模板：下跌/上涨链、
新闻计划、今日归因、行情、比较、账户和关注列表 fan-out、宏观、13F、命令。规划器和路由里 70 条
措辞正则全部删除；实体抽取（代码和公司名表）保留。`test_recorded_intents_reproduce_every_legacy_plan`
把每条标签跑一遍新规划器，和旧管线的路由、能力、回答模式、是否需确认逐项比对，作为模板的回归测试。
简报模板重做：宏观、财报日历、组合风险、关注列表，不再对持仓逐只归因。
`intent_report` 改为按来源、kind、wants 的分布和模型拿不准（置信度 < 0.7）、未分类的问题清单。

顺带的四处：评审员看得到规则针对的证据原文，"内部计数"规则只禁系统口径；反方、挑战者、评审员、
分类器全部通过单个 function 工具返回结果，不再解析文字 JSON；子智能体强制结束那一轮只提供 finish；
用量账本记推理 token（`completion_tokens_details.reasoning_tokens`），报告多一列"其中推理"；
含 `research.stock` 的计划预算提到 STANDARD。

## 框架补齐：评测闭环、共享状态、反方回流、可中断、工具箱、用户记忆

**评测闭环。** `eval/quality_cases.py` 是带评分标准的题集（13 条种子题：今日归因、英文问句、回撤链、
新闻、估值、比较、关注列表放量、持仓排名、财报日历、知识、简报、命令），每题有"必须满足"的标准、
"不得做出"的断言、必须引用的来源类型、预期路由和子智能体。`python -m v2.agent_v2.eval.quality run
--label 名字` 用线上运行时跑一遍，评分员（`agent_v2.quality_judge`，一次 function calling）逐条判定，
记录到 `data/agent_v2_quality.jsonl`；`... report` 给出每次运行的通过率、最近两次的逐题对照和最常未
满足的标准。用户的"不对"反馈会变成题目（`--feedback`）。

**运行内共享状态。** `ExecutionContext.board`（`RunBoard`）：每个任务能看到之前完成的结果和证据，
能申请追加任务（`board.request`），执行引擎在每一波之后把申请纳入计划，上限 4 条、不接受写操作、
同样的申请只接一次。第一个用户是新闻核查者：报道提到某天的申报而它没读到原文时，请申报阅读者去读。

**反方回流。** 反方有意见且剩余时间够时，合成器做一次有界修订（`revise`）：只在证据支持时补上被忽略
的候选或限制，修订稿过引用补全、校验器和评审员，不通过就保留原答案。Telegram 头部显示"按反方修订"
或"反方意见未采纳（原因）"。

**可中断。** 运行带 `cancel_event`；执行引擎在每一波之间、子智能体循环在每一轮之间检查，取消后剩余
任务标为跳过，结果状态 cancelled，已拿到的部分照常交付。Telegram 上回复"取消/停"即可；处理中的占位
消息按阶段更新（已识别问题、已规划 N 个任务、执行中：读申报…、整理回答、校验引用）并带秒数。

**共享工具箱和现场调查员。** `agents/toolbox.py` 把搜索、读正文、列申报、读章节、查记忆做成一处声明
的工具，带核对引文所需的状态；`agent.investigate` 是没有固定角色的子智能体，模型规划器给它任务、股票
和工具清单，它只报能在读到的正文里定位引文的发现。

**用户记忆。** `memory.py`：对上一条回答说"不对"/"反馈：…"/"👍"记录为反馈，"记住：…"/"以后…"记录为
偏好；偏好进入合成器的输入，负面反馈进入质量评测。

- 分类器多一个字段 `clarification`：confidence 低于 0.6、或缺了非问不可的信息（哪只股票、时间段、加关注
  还是设提醒、目标价）时给一句具体的反问。编排器在 confidence 低于 `clarify_below`（默认 0.6）且有反问时
  不规划，直接把反问返回（状态 waiting_clarification），并把原问题和反问记在会话里。
- 下一条消息按"原问题（补充：回复）"合并后重新分类和规划，这一轮不再反问；"取消"丢弃那个问题。
- 命令缺字段（"设置提醒需要方向和目标价"）走同一条路：下一条"跌到 150 的时候"补全成完整命令再进确认。
- 知识和帮助类问题、离线标签和默认意图不反问。新增质量题 q_clarify_alert（先"给AMD设个提醒"再"跌到150的
  时候"）。

## P4 对话记忆

- 会话记住上一轮的问题、回答全文（4000 字符内）和它引用的证据与结果，以及最近三轮的问答摘要。
- 分类器的输入多了 recent_turns（问题、回答摘要、股票），可以据此补全省略的股票和时间段；新字段
  refers_back 标记"针对上一条回答本身的追问"（展开某一点、为什么这么说、换口径重述）。
- refers_back 且会话里有上一轮证据时，不规划、不调用能力，合成器拿上一条回答全文加上一轮的证据写回答，
  照常过校验；Telegram 头部的合成信息带 follow_up。没有上一轮时按普通问题处理。
- 新增质量题：q_followup_expand（"QCOM有什么风险？"后"上面第二点展开讲"）、q_followup_why（"分析NVDA估值"
  后"为什么这么说？"）。
