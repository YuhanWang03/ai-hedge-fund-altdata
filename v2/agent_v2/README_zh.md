# Agent V2 — 证据约束的多智能体投研助手

[English](./README.md) | 中文

Agent V2 是这个仓库的对话层：Telegram 用户用中文或英文提问（"ARM买入以来跌了这么多，是什么原因？"、
"why did AMD drop today"、"上面第二点展开讲"），得到的回答里每一个数字都对应一条系统真正抓取过的证据——
行情、SEC 申报、新闻页面、账户、宏观面板——并且在发出之前经过校验。

它没有用任何 agent 框架：按模型意图驱动的确定性规划器、带 fan-out 和截止时间的执行引擎、跑在同一个通用
工具环上的一组有界子智能体、草稿必须通过引用校验器和模型评审的合成器，以及给每次改动在固定题集上打分的
评测环。

## 数字

在 VPS 上经生产运行时和生产模型（DeepSeek）测得；每题问两次，多数裁决：

| 运行 | 集 | 题数 | 通过 | 兜底 | 平均秒 | 当量/题 |
|---|---|---|---|---|---|---|
| dev1（加固循环起点） | 开发集 | 37 | 28 · 76% | 3 | 43.5 | 29,276 |
| dev3 | 开发集 | 37 | 32 · 86% | 0 | 44.1 | 28,286 |
| dev7 | 开发集 | 40 | 37 · 92% | 1 | 35.9 | 25,961 |
| dev8（定稿；加入三道调查题） | 开发集 | 43 | 37 · 86% | 1 | 48.5 | 27,008 |
| holdout2（定稿；迭代中从不看） | 留出集 | 13 | 10 · 77% | 0 | 36.4 | 29,816 |
| lab2（定稿；每题一次，每题几分钟） | 实验集 | 3 | 3 · 100% | 0 | 88.9 | 30,297 |

* **兜底**指校验器两次拒绝后换成确定性证据摘要的回答——安全，但平淡。
* **当量**按未缓存输入 ×1、缓存输入 ×1/30、输出 ×3 折算，不同时段的运行可以直接比，不受提供方分时定价影响。
* 211 个离线单测和 39 条离线评测（路由、回答纪律、两轮对话场景）用脚本化模型秒级跑完；CI 门禁在每次 push 上跑。

定稿的开发集里六道未通过题全部是一次过、一次不过（评审员对措辞标准的分歧，或模型第二次答法不同），没有一道
两次都挂。留出集比开发集低 15 个百分点，这是"循环见过的题"和"没见过的题"之间的真实差距：三道未通过里两道
是 1/2，一道（口语的"我买的 X 怎么亏成这样"）两次都挂，仍是开放问题。

## 一个问题是怎么被回答的

```
文本 ─▶ 规范化 ─▶ 意图（模型分类器；离线用录制标签）
     ─▶ 路由 ─▶ IntentPlanner（确定性模板） ─▶ StructuredLLMPlanner（有界细化）
     ─▶ ExecutionEngine：能力 DAG、对持仓的 fan-out、墙钟预算、
        运行板上的后续任务、取消
     ─▶ 需要判断的能力交给子智能体：
        move_attributor · news_checker · filing_reader · investigator · debater
     ─▶ LLMEvidenceSynthesizer：草稿 → 补引用 → 校验器 + 断言评审
        → 修复（一到两轮） → 确定性兜底
     ─▶ 辩论（一次反方审阅） → 有界修订
     ─▶ 结果：回答、证据、校验报告、子智能体轨迹、成本
```

规划之前先做两件事：分类置信度低于 0.6 且分类器点出了缺口的，先反问一句，下一条消息与原问题合并；针对上一条
回答本身的追问（"第二点展开讲"、"为什么这么说"）直接用上一轮的证据写，不再调用任何工具。

## 设计决策

**每个数字都引用证据，并由校验器核对。** 合成器只能陈述抓取到的证据支持的内容，每条事实后面必须写证据 id。
确定性校验器把草稿里的每个数字追溯到被引用的条目（允许四舍五入和单位换算，拒绝回答里没有展示的算术），检查
未知 id 和每个能力自带的规则；无法用模式匹配的措辞规则（"把候选解释写成了已确认的原因"）交给模型评审。
不通过的草稿带着校验器的具体异议去修复；第二次仍不通过就退回确定性摘要，而不是把未校验的数字发出去。
*代价：* 修复是模型开销里最大的一块；加固循环的大部分精力花在一次过率上（复述数字、开头句引用、同口径对照行、
排名表）。

**措辞规则用模型评审，不用正则。** 第一版用正则执行"盘中价不能叫收盘价"、"不要暴露内部驱动因素计数"，每换一种
说法就误报一次。现在规则是自然语言句子（`forbid_claim`），每个回答一次模型调用来评判，按内容缓存；只有精确的
检查（引用、数字、结构）保留为确定性检查。软规则只提示不拦截。

**确定性规划，按模型意图驱动，没有正则路由。** 分类器把措辞变成字段（kind、scope、direction、wants、tickers、
持仓或关注列表范围、命令细节、置信度、一句反问）。模板把字段映射到能力：带最差交易日和行业基准的回撤链、新闻
计划、账户和关注列表的 fan-out、大盘视图。离线有 560 条录制标签回放分类器，测试和评测不需要 key。模型规划器
可以细化研究计划，但从不替换固定模板。

**所有子智能体共用一个通用工具环。** 归因、新闻核查、申报阅读、调查员和辩论者都是"声明的工具 + finish 结构"
跑在同一个 `ToolLoop` 上：原生函数调用、JSON 文本兜底、每个环的轮次和秒数上限、一次强制收尾、轮次之间可取消。
提供方的怪癖（DeepSeek 思考模式拒绝指名的 `tool_choice`）只在环里处理一次。

**按证据形状的追问。** 会话保留上一轮的回答、证据和结果（精简版，最多十六个会话）。被分类器标为针对上一条回答的
追问直接从那份证据合成：几秒而不是一分钟，并且和任何回答一样经过校验。

**运维看得懂的成本账。** 每次模型调用都带 run id 和来源（分类器、规划器、各子智能体、评审、合成器）；报表按
来源、按运行、按问题给出 token 当量，并点名最贵的问题。

**用评测环代替盯 Telegram。** 四十道开发题带评分细则（模型评分员核对的标准、禁止的断言、期望的路由、子智能体
和来源类型、篇幅上限、多轮题的前置轮次，其中三道给调查员），十三道发版前跑、迭代中不看的留出题，以及三道按
实验答案形状评分的实验题（回测、参数扫描、事件研究；每题几分钟）。重复运行加多数裁决把模型抖动和真正的回归
分开。合并门禁秒级跑单测和离线评测（`scripts/agent_v2_gate.py`，CI 上也跑），加 `--live` 则把冒烟子集过一遍
真实模型。

**数据源健康是账本，不是日志。** 每次运行的每个能力结果都记录（状态、秒数、证据条数、第一个错误、限制条目
说核心模块失败的"空心"结果）。这份报告在上线一天内就找到了项目最大的两个时延来源（规划错误的 fan-out 让研究
运行超时；FRED 慢时宏观快照要几分钟）和一个线程故障（两个 worker 同时 import yfinance）。

**已知限制，写明。** 评审员和被评模型是同一家提供方，通过率有偏，留出集只能部分控制。数据提供方偶尔静默失败；
系统把结果标为部分并说明缺什么，而不是补全。待确认的写操作、反问和最近几轮存在 sqlite 里，重启不丢；上一轮的
完整证据不落盘，所以重启后针对上一条回答的追问按新问题处理，被重启打断的 chat 会被告知再问一次。调查员子智能体
有三类命名的活（事件的来龙去脉、申报的原文条款、某个说法的出处），各有固定简报和工具集；三道开发题给它评分。
申报条款和说法出处两题稳定通过；来龙去脉多数运行通过、在回答丢掉发现的引文时失败，是系统里最不稳的一项。

## 怎么跑

```
python scripts/agent_v2_gate.py                       # 单测 + 离线评测，秒级，不需要 key
python scripts/agent_v2_gate.py --live                # 再加冒烟子集过真实模型
python -m v2.agent_v2.eval.quality run --label NAME --repeat 2 --parallel 2
python -m v2.agent_v2.eval.quality run --set holdout --repeat 2
python -m v2.agent_v2.eval.quality run --set lab --label lab1   # 三道实验题，每题几分钟
python -m v2.agent_v2.eval.quality report --runs 3    # 每次运行的通过率、逐题矩阵、未满足的标准
python -m v2.agent_v2.eval.quality show q_compare      # 一道题的回答和裁决
python -m v2.agent_v2.eval.subagent_report --since 1  # 子智能体运行、按来源和按问题的 token 当量
python -m v2.agent_v2.eval.capability_report --since 1 # 数据源健康
python -m v2.agent_v2.eval.intent_report --since 7    # 分类器的决定和它的把握
```

线上运行时（`runtime.build_workspace_agent`）就是 Telegram bot 用的那一个；同一个
`AgentV2.run(text, session_id=..., cancel_event=...)` 也服务 web 门面和评测。

## 目录

```
v2/agent_v2/
  orchestrator.py   运行主循环：反问、追问、确认、执行、合成、辩论
  intent.py         分类器、录制标签、默认意图、决策账本
  planning.py       IntentPlanner 模板、预算、fan-out
  execution.py      能力注册表、引擎（DAG、fan-out、截止时间、运行板、排名表）
  llm.py            模型规划器、合成器（草稿/修复/压缩/修订）、载荷
  verification.py   引用和数字追溯、能力级规则、交评审的断言
  judge.py          断言评审
  session.py        短期会话：代词、待确认写操作、反问、上一轮
  memory.py         用户反馈和偏好
  agents/           base.py（ToolLoop、structured_call）、move_attributor、news_checker、filing_reader、toolbox（调查员）、debater
  adapters/         行情、研究引擎、申报历史、网页、旧响应器（带缓存）、实验室
  interfaces/       telegram、telegram_format、web
  eval/             评测题和 runner、留出集、离线套件、benchmark、账本和报表
```
